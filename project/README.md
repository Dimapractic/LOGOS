# LOGOS — интеграция ERP, WMS и TMS

Учебный проект по дисциплине **«Интеграция корпоративных систем»**.

Тема: **«Интеграция системы диспетчеризации транспорта (TMS) с WMS и ERP: проектирование сценариев „точно в срок“, SLA по времени отклика и механизмы повторных попыток»**.

## Запуск на Windows без интернета

1. Полностью распакуйте весь архив. Папки `project` и `runtime` должны оставаться рядом.
2. Дважды нажмите `START_OFFLINE.bat` в родительской папке или выполните `.\start.bat` из папки `project`.
3. Откроется http://127.0.0.1:8000. Оставьте терминал открытым; остановка — Ctrl+C.

Python 3.12.10 и зависимости для Windows 10/11 x64 (Intel/AMD) включены. Установка Python, интернет и VS Code для запуска не требуются. Для редактирования откройте `project` в VS Code.

Windows-исполнение в среде разработки не проверялось: перед защитой выполните контрольный запуск на ноутбуке.

### macOS / Linux

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python run.py
```

## Первая демонстрация

1. Оставьте модельное время на паузе.
2. Нажмите **«Новый заказ»**, укажите получателя, оставьте остальные значения и создайте заказ.
3. В течение нескольких секунд сервис интеграции зарезервирует товар в WMS, назначит машину в TMS и подтвердит план в ERP.
4. Откройте карточку заказа: там видны план, фактические отметки и HTTP-попытки.
5. Выберите скорость **«5 мин / сек»** и нажмите **«Запустить время»**. Через примерно 40 секунд модельного прогона заказ будет доставлен. Реальная длительность зависит от скорости и сбоев.
6. Посмотрите склад, транспорт и мониторинг. После доставки можно снова поставить время на паузу.

Модельное время изначально равно времени первого запуска. Оно сохраняется в БД; после перезапуска всегда стоит на паузе. Отображение дат — в часовом поясе браузера. Все сетевые тайм-ауты, SLA и задержки повторов считаются в реальных секундах, независимо от скорости модели.

## Что уже работает

- Четыре независимых HTTP-сервиса и четыре отдельные базы SQLite.
- Создание однопозиционного заказа в ERP; резервирование и отгрузка в WMS; назначение одной из пяти машин в TMS.
- Расчёт плана назад от окна доставки, ускоренная симуляция, фактические отметки, прогноз опоздания.
- Устойчивая очередь оркестратора, восстановление после перезапуска, автоматические и ручные повторы.
- Идемпотентные команды: одинаковый ключ и тело возвращают прежний результат без повторного изменения данных.
- Контроль конфликтующего повторного использования ключа.
- Имитация HTTP-ошибок, медленного ответа и потери подтверждения после успешной записи.
- До четырёх попыток с экспоненциальным увеличением задержек: 2, 4, 8 секунд плюс 0–0,3 секунды случайного разброса.
- Список остановленных операций, ручное возобновление, последовательная компенсация при отмене.
- Журнал времени ответа и доля успешных попыток в пределах SLA.
- Русскоязычный интерфейс, документация OpenAPI, сквозные тесты.

| Сервис | По умолчанию | Ответственность | База |

| Hub | 8000 | Интерфейс, очередь, планирование, SLA и повторы | hub.sqlite3 |

## Данные и сброс

Данные сохраняются при обычной остановке. Для чистой демонстрации **сначала остановите все сервисы**, затем переименуйте папку `data` в `data-backup` и запустите приложение. Создадутся новые базы с остатками 500 / 200 / 80 единиц. Старые данные останутся в резервной папке.

Не переименовывайте и не удаляйте базы при работающих процессах. В архиве баз нет, каждый запуск на новом компьютере начинается с чистого стенда.

## Проверки

После установки зависимостей:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты запускают собственные сервисы на свободном диапазоне портов и используют временные базы; ваши демонстрационные данные не изменяются.

Проверяются доставка, повтор после потери подтверждения без дублей, исчерпание попыток и ручной повтор, компенсация, бизнес-ошибка без повторов, перезапуск очереди, нарушение SLA при успешном ответе, конфликт ключа, валидация входных данных, настоящий HTTP-тайм-аут без двойного резерва и получение заказа из ERP после простоя Hub.

## Границы первой версии

Это локальный учебный стенд, а не промышленная TMS. Нет авторизации, реального GPS, карт, нескольких складов, подбора маршрутов и подключения к 1С/SAP. Не публикуйте этот локальный API в интернет без отдельной доработки доступа. Сервисы слушают только `127.0.0.1`.

Проверка занятости машин выполняется по плановым интервалам; динамическое перепланирование других перевозок при фактической задержке — следующий этап. Время сборки/пути задаётся пользователем. Детали упрощений и возможные доработки описаны в `ARCHITECTURE.md`.
