LOGOS 1.1 — КОМПЛЕКТ ДЛЯ СДАЧИ И ЗАЩИТЫ
Дисциплина: Интеграция корпоративных систем

СНАЧАЛА ПОЛНОСТЬЮ РАСПАКУЙТЕ АРХИВ.
Не запускайте программу из окна просмотра ZIP.

1. ЗАПУСК БЕЗ ИНТЕРНЕТА НА WINDOWS 10/11 x64

Дважды нажмите START_OFFLINE.bat в этой папке.
Python и библиотеки уже находятся в runtime. Ничего скачивать не требуется.
Откроется браузер: http://127.0.0.1:8000
Окно терминала оставьте открытым. Для остановки нажмите Ctrl+C.
Если браузер не открылся автоматически, введите указанный адрес вручную.

Переносная сборка предназначена для 64-разрядной Windows на Intel/AMD.
На Windows в среде разработки она не запускалась: обязательно выполните
контрольный запуск на своём ноутбуке до занятия. Зависимости проверены
на соответствие Windows x64 и Python 3.12.

Если нужен другой диапазон портов, в PowerShell этой папки:
  $env:DEMO_PORT = "8100"
  .\START_OFFLINE.bat
После этого адрес интерфейса: http://127.0.0.1:8100

Для редактирования откройте папку project в VS Code.
Сам VS Code не требуется для запуска программы и в комплект не входит.

2. ЧТО СДАВАТЬ

documents/LOGOS_report.docx — редактируемый отчёт, 12 страниц.
documents/LOGOS_report.pdf — версия отчёта для просмотра и печати.
presentation/LOGOS_defense.pptx — презентация, 10 слайдов, с заметками.
presentation/LOGOS_defense.pdf — версия слайдов для просмотра без PowerPoint.
project/ — исходный код, тесты, требования и описание API.

На титульном листе отчёта и первом слайде заполните ФИО и группу.
В отчёте также заполните организацию, кафедру и преподавателя.
После заполнения DOCX/PPTX при необходимости пересохраните PDF.

3. ДЛЯ ПОДГОТОВКИ К ЗАЩИТЕ

defense/Defense_notes.docx и .pdf — выступление, порядок показа,
короткие ответы на 10 вопросов.
project/DEMO.md — подробные сценарии сбоев.
assets/ — настоящие скриншоты работающего приложения.
tests/test-results.txt — протокол 10 успешных сквозных тестов.
tests/ui-results.json — результаты проверки интерфейса в Chromium.

4. ЗАПАСНОЙ ПОКАЗ БЕЗ PYTHON

Откройте demo/LOGOS_demo.html обычным браузером двойным щелчком.
Это отдельная демонстрация интерфейса на учебных данных.
Она работает без сервера и не заменяет реальную HTTP-интеграцию.
Изменения в ней не записываются в базы основной программы.

START_HERE.html — удобное оглавление комплекта с локальными ссылками.

5. ПРОВЕРКИ И ДАННЫЕ

TEST_OFFLINE.bat — 10 сквозных тестов на временных базах.
VERIFY_FILES.bat — проверка контрольных сумм исходного комплекта.
После редактирования кода или документов контрольные суммы изменятся.
Это ожидаемо и не означает, что программа повреждена.

Рабочие базы появятся в project/data. Перед сбросом остановите все сервисы,
затем переименуйте project/data в project/data-backup.
Следующий запуск создаст чистые базы. Папку runtime не удаляйте.

Основной проект проверен в Linux и Chromium: тесты пройдены, создание
заказа и повтор после двух отказов работают, внешние сетевые ресурсы
для интерфейса и Swagger не требуются. Windows-исполнение не проверено.

6. ГРАНИЦЫ УЧЕБНОГО ПРОЕКТА

ERP, WMS и TMS — отдельные имитаторы с настоящими API и своими SQLite.
Один склад, пять машин, одна позиция в заказе, заданные времена операций.
Нет GPS, реальных карт, авторизации и промышленных корпоративных адаптеров.
Адреса сервисов доступны только на локальном компьютере.

Официальные лицензии Python и библиотек сохранены в runtime.
Офлайн-зависимости Swagger и их лицензии: project/static/api.
Состав версий: project/requirements-windows-lock.txt.
